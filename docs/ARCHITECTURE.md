# 架构与适配说明

开发启动：`nvm use && npm ci && npm start`。这里只记录已经实现的机制及其边界。

## 本地数据流

Electron 的渲染进程只展示节点名称、类型、策略组、域名映射和状态。主进程通过限定的 IPC 方法读取配置、调用回环控制接口并处理文件。关闭 Node integration，开启 context isolation、renderer sandbox 和 CSP；不加载远程 UI，不允许页面导航、新窗口、网络请求或额外设备权限。

连接设置只保存用户选择的路径和客户端标识；控制接口密钥随配置读取，不另存进工具设置、不传给 UI。备份包含原配置，因此仍可能包含用户原有凭据，仅保存在本机用户数据目录。

## 客户端发现

标准 Clash Verge Rev 数据目录根据系统定位：macOS 的 Application Support、Windows 的 APPDATA、Linux 的 XDG_DATA_HOME。便携版或自定义目录使用用户选择的路径。只读取适配所需文件，不遍历整个用户目录。

通过 `profiles.yaml` 的 current / items / option.script 找到当前订阅与已有专属脚本。注册信息、订阅源文件及脚本 / 运行文件的内容校验值用于检测应用前后的改动。

独立 Mihomo 要求用户选择实际运行文件。控制 API 本身不证明文件路径；工具通过运行模式、规则数量及可识别规则字段核对所选文件和实际内核，但相同内容的两个文件无法仅凭 API 区分。已识别为 Clash Verge 管理的文件会拒绝独立接入。

## 持久化

Clash Verge Rev 的原脚本保持原文，不在主进程执行。通过 Acorn 检查标准同步 main 入口，再在末尾追加带版本、规范化映射和边界标记的片段。片段调用原 main，将分流规则前置到返回的 rules。再次编辑时精确核对并替换受管理后缀；被手工改动的后缀不会覆盖。

这依赖所适配版本在每次配置生成时重新读取并执行专属脚本。现有全局扩展和专属脚本的处理顺序以 Clash Verge Rev v2.4.7 官方实现为依据。订阅更新测试回放合成脚本，不等于已经在所有真实客户端版本完成更新验收。

独立 Mihomo 使用根节点 `x-node-switcher` 记录管理版本和映射。仅移除可精确确认位于 rules 开头的旧受管理规则，再前置新规则。没有改变的应用不生成重复事务。

参考：[Clash Verge Rev v2.4.7 配置生成](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.4.7/src-tauri/src/enhance/mod.rs)、[Mihomo 路由规则](https://wiki.metacubex.one/config/rules/)。

## 应用事务

1. 重新读取当前订阅，确认编辑基线未改变。
2. 读取实际节点、策略组、规则与运行模式，规范化域名并检查出口。
3. 构造候选运行配置，用用户已有内核的 `-t` 模式校验；候选文件在 finally 中删除。
4. 返回两分钟内有效的预览 ID，内容和凭据只保留在主进程内存。
5. 用户确认后获取进程内互斥和本地锁，再次校验内容、文件与实际规则。
6. 写入原文件备份、完整性校验值及 prepared 日志；每个文件通过同目录临时文件、fsync、rename 替换。
7. 重载本地内核，读取实际 rules 和 mode。规则数量与可识别字段必须一致，所有新增域名规则必须逐条一致。
8. 确认文件未被其他程序修改后，记录 committed。

外部客户端不共享本工具的锁，因此这不是跨程序的原子事务。内容校验可以发现大多数并发修改，但检查与 rename 之间仍有短暂竞态窗口。应用时应避免在其他客户端同时编辑配置；遇到检测到的冲突会停止恢复，不用旧备份强行覆盖后续版本。

## 回滚与中断恢复

事务记录包含原始与写入后的内容 hash、备份相对文件名、保护文件的 hash 和原始运行配置的 hash。恢复前先核验保护文件、目标文件与所有备份；只有目标仍是原版本或本工具写入版本时才恢复。

自动恢复确认原文件和原规则后，标记 rolled-back。无法确认恢复时标记 recovery-needed，并阻止后续应用。用户可在连接同一配置后重试恢复；恢复本身可重复执行。已成功的应用可以按时间逆序撤销，存在较新未撤销记录时不能跳过它恢复旧记录。

断电时的文件系统和内核状态不具备全局原子性；启动后检查 pending journal 才能发现并继续恢复。工具不提升权限，也不执行任意用户命令。

## 验证层次

- Node.js 测试：临时配置和本地模拟 API，含故障注入。
- Electron 自检：合成客户端、真实 IPC、真实 DOM 与截图，不操作私人配置。
- Mihomo 集成：独立进程、TUN 关闭、临时端口、两个本机 HTTP 代理出口及合成域名，核验代理链、规则、回滚和重启。
- 真实本机 preflight：只读连接和候选配置校验，不将私人配置作为测试夹具或上传。

源码的跨平台自动检查与实际桌面客户端验收分别记录；UI 和最终使用体验仍需用户验收。
