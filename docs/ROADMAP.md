# 路线图

本文记录计划，不构成平台支持或交付日期承诺。实施进度以 GitHub Issues 为准。

## 阶段 0：公开立项

- [x] 明确工具定位和首版边界。
- [x] 提供 README、贡献指南、开源许可证及 Issue 模板。
- [ ] 确认首发操作系统、桌面入口及核心使用场景。
- [ ] 核验目标客户端的控制接口、版本及认证差异。
- [ ] 选择技术方案，并记录依据与取舍。

## 阶段 1：最小可用版本

- [ ] 实现控制接口连接、认证、超时与错误处理。
- [ ] 展示可选择的策略组、节点和当前选择。
- [ ] 实现节点切换及切换后的状态回读。
- [ ] 支持常用节点及本机连接设置持久化。
- [ ] 实现凭据安全保存与清除，不将密钥写入日志。
- [ ] 补充隔离开发环境、启动说明和必要自动检查。
- [ ] 发布第一个可安装的预览版本。

### 首版关键验收

- 错误密钥、不可达接口和超时均能返回准确的失败状态。
- 仅对支持手动选择的策略组发起切换，不改写用户的代理配置文件。
- 切换后重新读取当前选择；请求失败或状态不一致时不显示成功。
- 连续快速操作不会让较早请求覆盖用户最后一次选择。
- 本机设置重启后可恢复，清除连接时同步清除对应凭据。
- 发布物和日志不包含开发者个人配置、订阅地址或密钥。

## 阶段 2：提升效率

- [ ] 快捷键及系统托盘 / 菜单栏入口。
- [ ] 节点搜索、分组和收藏排序。
- [ ] 按需测速及结果更新时间显示。
- [ ] 中英文界面与基础可访问性。

## 阶段 3：扩大兼容范围

- [ ] 基于反馈扩展 Windows、macOS、Linux 支持。
- [ ] 明确客户端与版本兼容矩阵。
- [ ] 评估其他控制接口适配与多配置切换。

## 待决策

以下事项需要在实现前讨论，当前不锁定技术路线：

| 决策 | 需要权衡 |
| --- | --- |
| 首发平台 | 用户需求、开发与验证成本、打包及签名成本 |
| 产品入口 | 桌面窗口、托盘 / 菜单栏、快捷键的学习成本与使用效率 |
| 技术方案 | 安装体积、跨平台能力、系统集成、维护成本 |
| 凭据保存 | 系统凭据库可用性、跨平台行为和故障处理 |

技术选型完成后，先建立项目独立依赖环境，再开始实现。
